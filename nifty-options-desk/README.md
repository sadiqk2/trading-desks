# NIFTY Options Desk

A fast, professional **NIFTY option-chain analytics terminal** that processes the chain and shows
the *evidence* behind bullish / bearish / range-bound setups. It never predicts and never places
trades — it explains **why** a setup exists and what would confirm or invalidate it.

## Run

```bash
node server.js          # → http://localhost:8081   (PORT=… to change)
```

`index.html` is self-contained and also opens directly in a browser.

## Live NSE data

```bash
node bridge/nse-bridge.js                 # from the repo root — live nseindia.com → 127.0.0.1:8082
NSE_FIXTURE=1 node bridge/nse-bridge.js   # demo pipeline with the bundled genuine snapshot
```

The dashboard auto-detects the bridge and shows **LIVE · NSE INDIA** (or **FIXTURE DATA**); without it the honest **SIM FEED** badge shows and the seeded simulator keeps running.

## What it does

| # | Panel | Function |
|---|-------|----------|
| 1 | Header | NIFTY spot + change, expiry, time-to-expiry, market status, update time, refresh, auto-refresh |
| 2 | Market Structure | Bullish / Bearish / Range-bound / Neutral from 10 evidence rows (trend, OI structure, call/put writing, short covering, volume, RSI, VWAP, price action) + **Signal Strength x/10 = confirmations, not probability** |
| 3 | Key Levels | Immediate + strong S/R from OI walls, OI change, volume, price action — with a horizontal price ladder |
| 4 | Option Chain | CE/PE table around ATM (LTP, %chg, vol, OI, OI Δ, IV) with HI OI / MAX ADD / MAX CUT / VOL badges and ATM marker |
| 5 | OI Interpretation | Every strike classified from **option price × OI**: LONG BUILDUP · CALL/PUT WRITING · SHORT COVERING · LONG UNWINDING |
| 6 | PCR | OI PCR, volume PCR, near-ATM PCR, PCR(Δ) with rising/falling — context only, never a signal |
| 7 | Setup Scanner | CE / PE / RANGE cards with exact condition checklists and actions (`WAIT FOR 23,200 BREAKOUT` …) |
| 8 | Alerts | Breakout / Breakdown watch with 5-condition confirmation → "BULLISH/BEARISH CONFIRMATION" |
| 9 | Contract Selector | Slight ITM / ATM / OTM with premium, Δ, Θ, IV, volume, OI, **bid-ask spread & liquidity** |
| 10 | Trade Plan | Direction, trigger, preferred contract, entry, SL, T1/T2, invalidation — scenario, not a promise |
| 11 | Risk Calculator | Position size, max ₹ risk, capital, loss at SL, profit at target, R:R, over-risk warning |
| 12 | Market Context | 15m/1H trend, VWAP, RSI(14), ATR, volume vs avg, India VIX + agreement count |
| 13 | Signal Log | Every setup recorded (time, spot, direction, strike, signal, reason, entry/SL/target, result) |

**Signal discipline** — a BUY-grade signal is never generated by one factor (high OI, high PCR,
extreme RSI or one loud option). The system distinguishes `OBSERVATION → SETUP FORMING →
CONFIRMATION → INVALIDATED` and shows the checkmarks that justify each state.

## Data architecture (swap-in live feeds)

The UI consumes a single normalized **Snapshot** and never touches provider internals:

```js
Snapshot {
  meta  : { provider, mode:'sim'|'live', asOf, ist, marketStatus,
            expiry, expiryISO, dteDays, dteText, lotSize }
  spot  : { ltp, chg, chgPct, prevClose, dayOpen, dayHigh, dayLow, vix,
            candles15m:[{t,o,h,l,c,v}] }        // t = candle-open epoch ms
  chain : [ { strike, ce: Leg, pe: Leg } ]
}
Leg {
  ltp, prevClose, chgPct, volume, oi, oiChg, iv,
  bid, ask, delta, thetaDay, prevOi, volAvg
}
```

* `MockOptionChainProvider` (in `index.html`, Layer 1) — realistic chain seeded from the genuine
  NSE chain snapshot of **25-Sep-2026 10:40 IST** (spot 23,068.60, expiry 29-Sep-2026), missing
  strikes synthesised via Black–Scholes with an IV smile. Ticks every second with delta/theta/vega
  dynamics and OI regimes that produce real buildup/writing/covering/unwinding patterns.
* **To go live**: implement `fetchLiveSnapshot()` in `server.js` (Kite Connect, Upstox, Fyers, or
  NSE via cookie-warmed session) so it returns the Snapshot schema — then point the app at
  `LiveProvider = { name, init, getSnapshot: () => fetch('/api/chain').then(r => r.json()) }`.
  Every panel keeps working without UI changes.

Layers inside `index.html` (kept separate on purpose):

```
Layer 1  DATA       provider interface + MockOptionChainProvider
Layer 2  ANALYTICS  classification · VWAP/RSI/ATR/trends · levels · PCR · evidence
Layer 3  SIGNALS    structure verdict · setup scanner · alerts · stage machine · plans
Layer 3b LOG       persistent signal log
Layer 4  UI         rendering + interaction only
```
